# 应用更新发布手册

## 当前版本

2026-11-11 的本地版本为 4.20.3，包含 phpStudy 站点导入和自定义更新源。

首次手动安装该版本，进入关于我们，填写并保存更新目录。随后检查更新、下载更新，确认后重启并安装。

## 更新包组成

Windows 使用 NSIS 安装包。每次发布保留同一应用名称及 appId，将以下三个文件放在同一目录。

```text
latest.yml
FlyEnv-Local-Setup-4.20.3.exe
FlyEnv-Local-Setup-4.20.3.exe.blockmap
```

- exe 是完整安装包。
- latest.yml 记录版本、安装包文件名、大小和 SHA-512。
- blockmap 用于差分下载，服务器需支持 HTTP Range。首次更新或差分不可用时，更新器下载完整安装包。

## 构建下一版

1. 修改根目录 package.json 的 version，后续版本应大于已安装版本，例如 4.20.4。
2. 按项目要求记录变更并运行测试。
3. 在 Windows 开发环境运行以下命令。

```powershell
yarn build:win
```

该命令生成 release 下的安装包、blockmap 和 latest.yml。Windows 文件版本跟随 package.json。

如果已有最终安装包，单独重新生成元数据可执行以下命令。生成时读取当前 package.json 版本，因此应在同一发布源码版本中操作。

```powershell
yarn update:manifest release/FlyEnv-Local-Setup-4.20.4.exe
```

安装包及 blockmap 就绪后再生成 latest.yml。生成完成后修改或重签 exe，须重新生成相应 blockmap 与元数据。

## 本机测试

在项目根目录启动静态服务。

```powershell
python -m http.server 9088 --bind 127.0.0.1 --directory release
```

在关于我们中填写 `http://127.0.0.1:9088/`，保存后检查。已安装版本低于 latest.yml 版本时可下载，否则显示已是最新版本。

本机测试使用正式安装版。开发模式会提示当前运行方式不支持自动更新。

## 以后部署远程地址

将 exe、blockmap 上传到服务器目录，确认可访问后最后上传 latest.yml，再将关于我们中的更新目录改为该目录的 HTTPS 地址。

例如填写 `https://你的服务器/updates/windows/`。地址应指向目录，省略 latest.yml 文件名。

服务器对最新元数据使用短缓存或关闭缓存，对已发布的带版本号文件保持内容稳定，并保留旧版本及其 blockmap 供差分下载使用。

## 行为说明

- 更新源偏好独立保存，默认空地址。空地址时启动自动检查跳过，手动检查提示配置。
- 更新按钮和启动自动检查使用同一控制器。任务跨页面保留，下载完成后由用户确认安装。
- 更新器校验安装包 SHA-512，校验失败不能安装。安装前调用应用既有停止流程。
- 本地打包使用回环占位地址生成 app-update.yml，实际更新请求使用关于我们中保存的地址。
- 当前产物为本地未签名 Windows x64 安装包。

实现依据为 electron-builder v26 的自动更新与发布机制。[官方自动更新文档](https://www.electron.build/v26/docs/features/auto-update/)
